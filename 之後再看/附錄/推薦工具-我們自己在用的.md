# 推薦工具｜我們自己每天在用的

> 這份是參考用的，**今天一個都不用裝**。
> 原則：**只推我們工作室真的在用的**。沒用過的，我不會寫在這裡。

---

## 先說為什麼「今天不要裝」

你現在的助理只看得到一個資料夾，這樣很乾淨。裝工具是給它「長手」——能連到外面的東西。

但新手最常見的坑是：**一口氣裝十個，結果九個用不到，還把自己搞混。**

正確的順序是：**先用兩週 → 遇到一件「它要是能連到 ○○ 就好了」的事 → 才去裝那一個。**

所以這份請你收著，等你心裡冒出那句「要是它能…就好了」再回來翻。

---

## 一、MCP：讓它連到外面的東西

MCP 就是一條接線。裝一條，它就多一個能碰到的地方。

### 推薦三個（照我們實際用的頻率排）

**① Firecrawl — 讀網頁**

我們每天都在用。給它一個網址，它會把整頁內容讀進來。

實際用途：
- 「幫我看這家競品的官網在賣什麼」
- 「把這篇官方說明讀一讀，告訴我重點」
- 查證——我們寫任何對外的東西之前，都用它去把事實查過一遍

對小店老闆最有感的場景：**寫文案前先看一下同業怎麼講**。

**② Google 日曆／Gmail／雲端硬碟**

這組最適合已經在用 Google 的人（大部分人都是）。

實際用途：
- 「這週有哪些事要先準備？」
- 「今天有哪幾封是客人問價的？」
- 「把上個月的報價單整理成一張表」

**③ Playwright — 操作瀏覽器**

讓它真的打開瀏覽器點東西、截圖。

實際用途：我們用它看自己做的網頁在手機上長什麼樣、要登入才看得到的後台數字也靠它。

這個比較進階，但如果你常常要「去某個後台抄數字」，它會幫你省很多時間。

---

### 我們有裝、但先不推薦給你的

誠實講一下，免得你以為我藏私：

| 工具 | 為什麼先不推 |
|---|---|
| Filesystem（讀整台電腦的檔案） | 跟「只給它一個資料夾」的安全原則相衝。等你很熟了再說 |
| NotebookLM | 適合一次讀幾十份文件做研究，小店日常用不到 |
| 記憶宮殿（長期記憶系統） | 等你真的覺得「它老是忘記」再裝，現在裝只會多一層複雜 |

## 二、skill：讓它記住「怎麼做某件事」

skill 是一張 SOP 小卡。推薦三個：

**① 自己寫的那一個（最重要）**

認真的——**你最該有的 skill，是你自己工作流程的那一張**。

11/2 直播我們做的「這週的店家週報」，把它存成 skill 就是你的第一個。別人寫的再好，都不會比你自己每週在做的那件事更貼身。

**② 官方的 skill-creator**

Anthropic 官方出的，教你把流程做成 skill。
`github.com/anthropics/skills` → `skills/skill-creator`

**③ 處理文件的那組（docx／pdf／xlsx）**

也是官方的，在同一個 repo。要它幫你做報價單、讀 PDF、整理試算表的時候會用到。

我們工作室做客戶報價單、讀政府公告 PDF 都靠這組。

---

## 三、GitHub：一個入口就好

GitHub 是大家把寫好的東西公開放的地方。

**你需要知道的只有兩件事**：

1. 官方的東西在 `github.com/anthropics/skills`——這個最安全，先從這裡找
2. 看到任何別人推薦的，**先過三問**（看 `之後再看/說明/安全-裝別人的東西之前.md`）

我故意不給你一長串清單。**清單會讓人亂裝**，而亂裝正是這份文件最想避免的事。

想找東西的時候，直接問你的助理：

```
我想找一個可以幫我（做某件事）的 skill。
先幫我找兩三個，說明各自是誰寫的、會動到什麼，我再決定要不要裝。
```

## 最後

這份的每一個工具，我們工作室都在用，不是抄來的清單。

但**用不到的工具，裝了只是負擔**。先把你手上這個助理用熟——它認得你的品牌、照你的規則做事、東西會自己存檔——這樣就已經比大多數人走得前面了。
